1. Conceptos clave

Cada usuario tiene tres atributos que, combinados, definen lo que ve y lo que puede hacer:

AtributoQué defineEjemplo
PerfilQué puede hacer: el conjunto de permisos (crear fincas, crear proyectos, dictaminar, validar documentos, etc.). Se configura en una matriz. Podés crear perfiles nuevos.Administrador, Responsable RIMI, Líder de proyecto, Compras, Impuestos, Contabilidad, Administración/Tesorería/Técnico, Sólo lectura, o uno propio.
Rol funcional (área)Qué tareas le tocan: las tareas automáticas de cada etapa se asignan por rol. También puede sumar permisos extra y habilita a mover la etapa cuando ese rol es el responsable de la etapa actual.Responsable del Proyecto, Compras, Impuestos, Contabilidad, Tesorería, Personal técnico.
EmpresasQué datos ve: un usuario sólo ve las zonas, fincas y proyectos de las empresas que tiene habilitadas.Solfrut y/o Genética Incarí.
Regla de oro: Permisos efectivos = permisos del perfil + permisos extra del rol funcional. El perfil Administrador tiene todo, más el acceso a Administración. Un perfil sin ningún permiso es de sólo lectura.

Además, el Responsable de un proyecto (campo “Responsable del Proyecto” de la ficha) siempre puede editar su proyecto: la ficha, los bienes, el checklist, las tareas y el equipo, aunque su perfil no tenga los permisos generales.

3.3 Cambiar permisos de un perfil

  1. Entrá a Administración → Perfiles y permisos.
  2. En la matriz, cada columna es un perfil y cada fila un permiso. Tildá o destildá las casillas.
  3. Presioná Guardar cambios. Se aplican en la próxima acción de cada usuario, sin cerrar sesión.

3.4 Crear un perfil nuevo

  1. En Perfiles y permisos, presioná Nuevo perfil.
  2. Cargá el nombre, el color y la descripción. En “Copiar permisos de” elegí un perfil como punto de partida, o dejalo sin permisos (sólo lectura).
  3. Guardá y ajustá los permisos en la matriz.
  4. Asignalo a los usuarios desde Usuarios y accesos.
Un perfil sólo se puede eliminar si ningún usuario lo tiene asignado. Los perfiles base no se eliminan.

4. Roles funcionales y permisos extra

Los roles funcionales representan las áreas del procedimiento. Cumplen tres funciones:

  1. Asignación automática de tareas: al entrar un proyecto en una etapa, cada tarea de la plantilla se asigna al usuario del proyecto con ese rol o, si no hay, a un usuario con ese rol en la misma empresa.
  2. Responsable de etapa: quien tiene el rol de la etapa actual puede avanzar el proyecto (ej. Contabilidad avanza desde “Tratamiento contable”).
  3. Permisos extra: se suman a los del perfil.

5. Alta, edición y baja de usuarios

5.1 Alta manual

  1. Administración → Usuarios y accesos → Nuevo usuario.
  2. Completá correo, nombre, cargo y teléfono.
  3. Elegí Perfil (qué puede hacer), Rol funcional (qué tareas le tocan) y Empresas (qué ve).
  4. Guardá. El sistema muestra una contraseña temporal: copiala y enviala por un canal seguro. En el primer ingreso, el sistema obliga a cambiarla.
Si la organización usa Microsoft 365, podés crear el usuario con el mismo correo corporativo: cuando ingrese con Microsoft, se vincula automáticamente a su cuenta y conserva el perfil, el rol y las empresas que le asignaste.

5.2 Edición, baja y recuperación

  • Cambiar perfil, rol o empresas: abrí el usuario y modificá los campos. El efecto es inmediato.
  • Baja: desactivá al usuario. Se conserva su historial y no puede volver a ingresar, ni siquiera con Microsoft.
  • Olvido de contraseña: “Restablecer contraseña” genera una nueva clave temporal.

6. Validación con Microsoft 365 (Entra ID)

RIMI Hub permite el inicio de sesión único (SSO) con las cuentas corporativas, usando OAuth 2.0 / OpenID Connect con PKCE. La contraseña la valida Microsoft (incluido MFA si está activo); el portal nunca la ve.

6.1 Lo que tiene que hacer Sistemas en Azure (una sola vez)

  1. En portal.azure.com → Microsoft Entra ID → App registrations → New registration: nombre “RIMI Hub”, tipo de cuenta sólo este directorio organizativo (single tenant).
  2. Redirect URI (plataforma Web): https://<dominio-definitivo>/auth/microsoft/callback. La URI exacta se muestra en Administración → Microsoft 365 / Azure, con botón para copiar.
  3. API permissions: Microsoft Graph, delegados openid, profile, email y User.Read → Grant admin consent.
  4. Certificates & secrets → New client secret: copiá el Value (no el ID) y anotá el vencimiento.
  5. Desde la pantalla Overview, anotá el Directory (tenant) ID y el Application (client) ID.

6.2 Cargar los datos en el servidor

Los datos se cargan como secretos del servidor, no en la base de datos ni en el navegador:

SecretoValor
MS_TENANT_IDDirectory (tenant) ID
MS_CLIENT_IDApplication (client) ID
MS_CLIENT_SECRETValue del client secret
APP_URLURL pública del portal, sin “/” al final

Cuando estén cargados, la pantalla de Microsoft 365 pasa de “Pendiente” a “Configurado”.

6.4 Cómo validar que funciona

  1. Con un usuario de prueba del dominio, presioná “Ingresar con Microsoft 365”. Debe aparecer la pantalla de Microsoft y luego volver al portal con la sesión iniciada.
  2. Verificá en Usuarios y accesos que el usuario figure con origen Microsoft. Si fue un alta automática, asignale perfil, rol y empresas.
  3. Probá con un correo de un dominio no permitido: debe mostrar “El dominio … no está habilitado”.
  4. Desactivá un usuario e intentá ingresar: debe mostrar “Tu usuario está deshabilitado”.
  5. Revisá Auditoría: allí quedan los ingresos y los intentos fallidos.
Errores frecuentes: AADSTS50011 significa que la Redirect URI no coincide (revisar APP_URL y la URI registrada, incluido https y sin barra final). AADSTS7000215 indica un client secret inválido o vencido (se cargó el ID en lugar del Value, o venció). AADSTS65001 aparece cuando falta el consentimiento del administrador. Agendá la renovación del secret antes de su vencimiento.

Estado actual: la integración está programada y probada en modo “no configurado”; faltan las credenciales que debe entregar Sistemas y el dominio definitivo del portal.

7. Constructor de formularios

En Administración → Constructor de formularios elegís “Ficha de proyecto” o “Inversión / bien”.

  • Agregar: hacé clic en un tipo de campo de la paleta (texto, número, importe, fecha, lista, NCM, usuario…).
  • Editar: con el lápiz cambiás etiqueta, sección, ancho, opciones, ayuda y si es obligatorio, visible o de sólo lectura.
  • Reordenar: arrastrá campos entre secciones y secciones entre sí.
  • Eliminar: con el ícono de papelera de la tarjeta (o “Eliminar campo” en el editor). El campo pasa a la Papelera, al final de la pantalla.
  • Restaurar: en la Papelera, “Restaurar” devuelve el campo con los datos que ya tenía cargados.
  • Borrar definitivamente: la ✕ de la Papelera, disponible sólo para campos personalizados.
Tipo de campoEliminar (Papelera)Borrar definitivamente
Personalizado (creado por ustedes)✔✔
Del sistema (Anexo I: fechas, presupuesto, dictamen…)✔— (queda en Papelera, puede figurar en reportes/Excel)
Estructural (candado): Nombre, Código, Empresa, Zona, Tipo, Responsable · Descripción del bien— (organizan los datos)—

Al eliminar una sección, sus campos pasan a la Papelera. Si contiene un campo estructural, primero hay que moverlo a otra sección.

8. Flujo de trabajo paso a paso

Estructura de datos: Empresa → Zona → Finca → Proyecto → Inversiones (bienes). El proyecto recorre 9 etapas. En cada etapa se generan tareas automáticas para cada rol y se notifica al equipo. Puede mover la etapa: quien tenga “Mover cualquier etapa” (RIMI, Admin), el rol responsable de la etapa actual, o el Responsable del Proyecto mientras la ficha está en preparación.

Revisión realizada (noviembre 2026): se recorrió un proyecto completo de las 9 etapas con los usuarios demo de cada área: 34 de 34 comprobaciones correctas. Se generaron 23 tareas automáticas, cada una asignada al área correcta, y se confirmaron los bloqueos esperados (Compras no crea fincas, el Resp. de proyecto no crea zonas ni dictamina, Tesorería no valida documentos, Dirección no escribe, Contabilidad no cierra el proyecto, RIMI no elimina proyectos).

11. Auditoría y buenas prácticas

  • Todo cambio de perfiles, roles, campos, etapas, documentos e ingresos queda en Auditoría y en el historial de cada proyecto.
  • Mantené al menos dos administradores activos.
  • Preferí ajustar roles funcionales para necesidades de un área y perfiles para cambios generales.
  • Con Microsoft 365, usá alta automática con perfil Sólo lectura y revisá las notificaciones de “Nuevo usuario”.
  • Antes de producción: desactivá los usuarios demo, cargá los secretos de Microsoft y definí los dominios permitidos.
